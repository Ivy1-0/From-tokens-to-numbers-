From Tokens to Numbers

This page shows the answer to every exercise in the lab, how to work it out, and why it works. Each section has the same layout: theory first, then the code you write, then what you should see.

The big idea: a computer cannot measure a list of words. We turn each document into a row of numbers, and then ordinary maths (sums, logs, angles) works on text. But how you fill the row decides what you can find.

1. The Document–Term Matrix

Theory

A document–term matrix (DTM) has one row per document, one column per word in the vocabulary, and a count in each cell. Word order is thrown away (the “bag of words” assumption). The vocabulary is every distinct word in the whole corpus, which is why it is built from all documents together.

CountVectorizer does three jobs: split the text, build the vocabulary, count. By default it uses a crude splitter. The analyzer argument lets you replace the whole text-to-tokens step with your own function.

Exercise 1.1 answer

Example
cv = CountVectorizer(analyzer=spacy_tokens)   # no brackets!
X = cv.fit_transform(meta["text"])
shape: (9, 418) -> 9 documents, 418 words
Common mistake: analyzer=spacy_tokens() calls the function immediately and fails. You pass the function itself so the vectoriser can call it on each document.

Why the vocabulary shrinks: spacy_tokens drops stop words and punctuation and lemmatises, so programmes and programme become one column.

Take-away: the matrix is not the text, it is one representation of it. Change the tokeniser and every later number changes. Always report your tokeniser, model version and stop-word list.

2. Sparsity and Hapax Legomena

Theory

sparsity = 1 − (non-zero cells ÷ total cells)

Most words appear in few documents, so most cells are 0. A sparse matrix stores only the non-zero cells (their values and positions), so memory grows with the number of non-zeros, not with rows × columns. A dense 100,000 × 200,000 matrix at 8 bytes per cell needs 160 GB.

Hapax legomena are words occurring exactly once in the corpus; dis legomena occur exactly twice.

Exercise 2.1 answer

Example
hapax_count = (frequencies == 1).sum()
dis_count   = (frequencies == 2).sum()
hapax_share = round(100 * hapax_count / len(frequencies), 1)
occur exactly once (hapax): 213 occur exactly twice (dis): 11 hapax as share of vocabulary: 51.0 %

How it works: frequencies == 1 makes an array of True/False. Python treats True as 1, so .sum() counts the Trues. Dividing by the vocabulary size gives the proportion.

Take-away: sparsity is a law-like feature of language, not bad data. About half of the vocabulary is hapax, and dropping it (min_df=2) suits topic modelling but can destroy evidence in authorship work.

3. Zipf and Herdan–Heaps

Theory

Zipf: f × r = k   |   Heaps: V = K × Nβ

Zipf’s law: frequency f falls in proportion to rank r. Taking logs of f = k/r gives log f = log k − log r, a straight line with slope −1 on log–log axes.

Herdan–Heaps’ law: vocabulary V grows as a power of the number of tokens N. Taking logs gives log V = log K + β log N, so β is the slope of a straight-line fit. Typical β is 0.4–0.6.

Exercise 3.1 answer

Example
for i in range(len(all_tokens)):
    word = all_tokens[i]
    seen.add(word)                     # a set keeps each word once
    if (i + 1) % 200 == 0:           # true at 200, 400, 600 ...
        n_tokens.append(i + 1)
        n_types.append(len(seen))      # vocabulary size so far
recorded 38 points final vocabulary: 513 words from 7600 tokens estimated beta: 0.48

Why a set? Adding a word already in a set does nothing, so len(seen) is always the number of different words read so far. % is the remainder after division, so % 200 == 0 fires once every 200 tokens.

Be sceptical: our Zipf slope is about −1.41, not −1, and β = 0.48 sits in the expected range partly by luck. The corpus is only ~7,600 tokens. Try changing 200 to 50 and watch β move.

Why this matters: Zipf says a handful of words (the, of, and) dominate every count. Heaps says the words that tell documents apart live in the rare long tail. Raw counts therefore reward exactly the wrong words.

4. Weighting and tf-idf

Theory

tf-idf(t, d) = tf(t, d) × idf(t)    idf(t) = ln((1 + n) ÷ (1 + df(t))) + 1

tf is how often the term is in this document. df is how many documents contain it, and n is the total number of documents. A word in every document gets the smallest idf; a word in one document gets the largest. The product is high only when a word is frequent here and rare elsewhere.

You can check the table by hand with n = 9:

dfCalculationidf
9 (every speech)ln(10/10) + 11.0
1 (one speech)ln(10/2) + 12.609

Those are exactly the lowest and highest values in the notebook output.

Example
cv_nostop = CountVectorizer(stop_words="english")   # 4.1

Reading the table: removing stop words helps, but people, year and congress are still shared by every speaker. Only tf-idf surfaces what is distinctive. Swapping weighting schemes means changing one class name; the interface is identical.

Caveat: idf belongs to your corpus, not the language. In a corpus of papers all about photosynthesis, that word gets a low idf. tf-idf measures distinctiveness within a collection, which is not the same as importance.

5. Cosine Similarity

Theory

cos(θ) = (a · b) ÷ (‖a‖ ‖b‖)

Each document is a vector. Cosine similarity is the angle between two vectors, so it ignores length: a short and a long speech on the same topic still score as close. It is 1 for identical direction and 0 when the documents share no words (word counts are never negative).

Exercises 5.1 and 5.2 answers

Example
if meta.loc[i, "president"] == meta.loc[j, "president"]:
    same.append(score)
else:
    different.append(score)

within_raw, between_raw = compare_within_and_between(X_raw)
tf-idf same 0.925 different 0.259 gap 0.666 raw counts same 0.995 different 0.920 gap 0.075

How it works: the loop starts j at i + 1, so each pair is counted once and the diagonal (a document against itself) is skipped. The if sorts each score by whether the two speeches share a speaker, then np.mean averages each list.

Why the raw counts fail: every speech is mostly function words, so every vector points the same way and even unrelated speeches score about 0.92. tf-idf removes that shared background, so the speaker blocks stand out (0.93 inside a block, about 0.26 outside).

Take-away: a cosine score alone means nothing. Compare it with a baseline from the same matrix, here the gap between same-speaker and different-speaker pairs, and never compare scores across different pipelines.
